## Économie de tokens
- Réponses courtes et directes : pas d'introduction, pas de reformulation de la demande, pas de résumé final.
- Ne répète pas le code ou les fichiers que je viens de voir ; montre seulement les lignes modifiées.
- Lis uniquement les fichiers nécessaires, et seulement les parties utiles (offset/limit) pour les gros fichiers.
- Préfère Grep/Glob ciblés à l'exploration large du projet.
- Pas de commentaires évidents dans le code, pas de refactoring ni de fonctionnalités non demandés.
- Fais le changement minimal qui résout le problème.
- Pose une question seulement si une erreur coûterait cher ; sinon, fais le choix raisonnable et dis-le en une ligne.
